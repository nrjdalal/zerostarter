# Init

Turn a fresh zerostarter scaffold into a blank product canvas: keep the engineering (the monorepo, auth, database, API, and tooling), drop everything that is zerostarter-the-product (its landing, its content, its branding, its dev-meta). This is the one-time companion to `fork-sync`, which re-baselines an already-converted fork on later upstream changes.

Run in a fresh clone of the fork (a `gitpick`ed zerostarter), on a branch off `canary`. Brand identity is centralized: code reads from `@packages/config/site`, so swapping that one file rebrands every dynamic surface. The work that remains is the content, assets, and meta that cannot be config-driven.

Gather the product's identity first: name, description, tagline, GitHub/X/Discord URLs, agent name and email, repo owner and name, author, license holder, and the production URL.

## Procedure

1. **Brand identity (the one file).** Edit `packages/config/src/site.ts`: `name`, `description`, `tagline`, `social.{github,x,discord}`, `agent.{name,email}`. Set `llmsFullPreamble` and `apiReferenceDescription` to the product's own text or to empty strings (the defaults are zerostarter dev-meta a product must not expose). Everything that renders identity (page metadata, OG images, the llms.txt header, sitemap, robots, the API reference) reads from here and rebrands automatically.

2. **Identity in config and meta.** Swap the remaining hardcoded identity:
   - `package.json` (root): `name`, `homepage`, `bugs`, `repository`, `funding`, `author`.
   - `README.md`: rewrite for the product.
   - `LICENSE.md`: the copyright holder.
   - `.github/FUNDING.yml`, `.github/rulesets/{main,canary}.json` (`source`), `.github/scripts/changelog-manager.ts` (the fallback owner and name), `.github/scripts/build-sizes.ts` (the graph root label), `docker-compose.yml` (`name`), `.env.example` (the two doc-link comments).
   - `.infisical.json`: set the fork's own `workspaceId`, or delete the file if you are not using Infisical.
   - Keep generic: `web/next/vercel.json`, `api/hono/vercel.json`, and the `@web/next` / `@api/hono` / `@packages/*` workspace names (rescope only if you want to).

3. **Marketing and personal pages.** Replace `web/next/src/app/page.tsx` with a generic product home (drop the testimonials, the "Why zerostarter" copy, the `cd zerostarter` snippet, and the social-proof line). Delete the personal routes `web/next/src/app/hire/` and `web/next/src/app/resume/`.

4. **Blog: strip to one format anchor.** The posts are zerostarter's own. Keep `web/next/content/blog/mcp-per-workspace.mdx` as a structure template (sections, SVG diagrams, code, numbered steps) and replace its content with a first product post, or delete it once you have your own. Delete the other posts. Genericize `blog/index.mdx` and update `blog/meta.json` to the kept set. A post's images live under `web/next/public/blog/<slug>/images/` and ride along until the content is replaced.

5. **Docs: strip to one format anchor.** zerostarter's docs are self-documenting (they describe the starter's own stack and tooling), so a product publishes its own. Keep `web/next/content/docs/index.mdx` as the docs entry and format anchor (replace its content) and the console `runbooks/incident-response.mdx` as a generic runbook template. Strip the rest under `web/next/content/docs/` and `web/next/content/console/docs/`. Regenerate `web/next/docs.config.ts` for the product's own doc set (it reads `site.name`, so naming rebrands automatically), and update the console `meta.json`.

6. **Assets.** Replace the branded OG fallback `web/next/public/og/home.png` and the favicon/app icon. Drop the per-repo dependency graph `web/next/public/graph-build.svg` and `.github/assets/graph-build.svg` (CI regenerates them). Prune the create-next-app demo svgs `web/next/public/{file,globe,window,next,vercel}.svg`. The tech logos under `web/next/public/landing/` are generic: keep them if the new landing keeps a tech section, otherwise prune them with `page.tsx`.

7. **Agent and meta docs.** Scrub the starter references in `AGENTS.md` (and its `CLAUDE.md` symlink): the `AgentZero` / `agent@zerostarter.dev` local-agent identity and the "zerostarter" mentions. Scrub the zerostarter mentions in `.agents/skills/{dev,fonts,docker-test}/SKILL.md`. Remove the author-attribution comment in `web/next/src/components/mode-toggle.tsx`.

8. **Do not port generated files.** Leave `CHANGELOG.md` to be regenerated by the product's own releases; do not carry zerostarter's history forward.

9. **Verify.** `bun install`; `SKIP_ENV_VALIDATION=true bun run build`; then brand-scan the tree, `rg -i "zerostarter|nrjdalal|neeraj|dalal|agentzero" --glob '!CHANGELOG.md'` should return only intentional references (for example a `fork-sync` note about the upstream). Confirm a preview deploys: preview env values must come from the fork's own validated `canary` scope, not placeholders, or `@packages/*` env validation fails the real build.

10. **Finish.** `init` is one-time, so you can remove `.agents/skills/init/` after this run. Keep `fork-sync` to pull future upstream changes (or remove it too if the fork will not re-baseline). Commit (conventional, no Co-authored-by), push, and open a PR to the fork's `canary`. Do not merge without review; squash-merge so canary stays one commit per PR.

## Init vs fork-sync

- **init** (this skill): the one-time conversion of a fresh zerostarter into a product. Run it once.
- **fork-sync**: re-baseline an already-converted fork on zerostarter's later changes, preserving the product and pruning starter-only artifacts. Run it whenever you pull upstream.
