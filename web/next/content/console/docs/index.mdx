This documentation is private. It is served only inside the access-protected
`/console` area and is never exposed through public search, the sitemap, or the
`llms.txt` indexes.

## Access

Console access is controlled by the user's `role` (the [Better Auth Admin plugin](https://www.better-auth.com/docs/plugins/admin)); only `role === "admin"` may enter `/console`.

- **Bootstrap:** list emails in `CONSOLE_ADMIN_EMAILS` (comma-separated env var). A matching, email-verified account is promoted to `admin` on **every sign-in**, so adding an email (even for an existing account) and re-logging-in grants access with no manual database edit.
- **Grant/revoke at runtime:** an existing admin uses the plugin's `setRole` (or `UPDATE "user" SET role = 'admin' WHERE email = '…';`). Roles are `admin` and the default `user`; finer tiers can be added later via the plugin's access control.
- The console guard reads the session with `disableCookieCache`, so a role change takes effect on the next `/console` request (it does not wait out the 5-minute `session.cookieCache`). To cut off an account everywhere immediately, ban it or revoke its sessions.

## Adding pages

Drop MDX files into `web/next/content/console/docs`. They are loaded through the
dedicated `consoleDocs` Fumadocs collection and inherit the same access checks
as the rest of the console.
