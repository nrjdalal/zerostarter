This documentation is private. It is served only inside the access-protected
`/console` area and is never exposed through public search, the sitemap, or the
`llms.txt` indexes.

## Access

Console access is granted when **either** the user's `role === "admin"` ([Better Auth Admin plugin](https://www.better-auth.com/docs/plugins/admin)) **or** their verified email is listed in `CONSOLE_ADMIN_EMAILS`.

- **Bootstrap root admins (env):** list emails in `CONSOLE_ADMIN_EMAILS` (comma-separated). The gate matches them against the signed-in user's email, so a listed account gets access with no DB write and no re-login. Break-glass for a fresh deploy.
- **Dashboard-assigned roles (DB):** an admin sets `user.role` via the plugin's `setRole` (or `UPDATE "user" SET role = 'admin' WHERE email = '…';`). Roles are `admin` and the default `user`; finer tiers can be added later via the plugin's access control.
- The check runs only on `/console` requests (against the already-loaded session), so normal logins never pay for it. The guard reads the session with `disableCookieCache`, so a role change takes effect on the next request (it does not wait out the 5-minute `session.cookieCache`). To cut off an account everywhere immediately, ban it or revoke its sessions.

## Adding pages

Drop MDX files into `web/next/content/console/docs`. They are loaded through the
dedicated `consoleDocs` Fumadocs collection and inherit the same access checks
as the rest of the console.
