## Overview

Blog content lives in `web/next/content/blog/` as MDX files. The blog is content-driven: each post owns its metadata in frontmatter, and the listing, ordering, and `meta.json` are all derived from the posts. Adding a post is a single file, with no list or `meta.json` to maintain by hand.

## Creating a Blog Post

1. Create a new `.mdx` file in `web/next/content/blog/`.
2. Add frontmatter with `title`, `description`, and `date` (all required), plus optional `draft`, `author`, and `tags`. The date is a `YYYY-MM-DD` value, quoted or unquoted (it is normalized to an ISO date string):

```yaml
---
title: "My Post Title"
description: "A short summary of the post."
date: 2026-06-11
---
```

3. Write the post body in MDX.

That is the whole workflow. Published posts appear on `/blog` automatically (newest first by `date`), and the page order updates itself. You never edit the listing or `meta.json` by hand.

## Drafts and Scheduled Posts

Add `draft: true` to hide a post regardless of its date:

```yaml
---
title: "My Draft"
description: "A post that is not ready yet."
date: 2026-07-01
draft: true
---
```

Use `date` as the publish date. A post with a future date and no `draft: true` is scheduled: it is excluded from `/blog`, direct blog routes, `sitemap.xml`, `llms.txt`, and OG image routes until that date passes. These public surfaces prebuild posts that are published at build time, then evaluate publishing during render/revalidation for future posts, so scheduled posts do not need a rebuild to become accessible and should appear within about 60 seconds.

Images for a post are committed as static assets under `web/next/public/blog/<slug>/images/` and referenced by absolute path, e.g. `![Diagram](/blog/<slug>/images/diagram.svg)`.

## How It Works

- **Schema**: the `blog` collection in `web/next/source.config.ts` requires `date` (and accepts optional `draft`/`author`/`tags`), so every post is validated at build time.
- **Publishing**: `web/next/src/lib/blog.ts` defines the shared hybrid static/ISR rule for published posts: not draft and not future-dated. The blog routes, listing, sitemap, `llms.txt`, and OG image routes all use that rule.
- **Listing**: `/blog` renders the `<BlogList />` component (`web/next/src/components/blog-list.tsx`), which displays published posts newest-first by `date`. `web/next/content/blog/index.mdx` only holds the page intro plus `<BlogList />`.
- **meta.json**: `web/next/content/blog/meta.json` is generated by the docs generator (`.github/scripts/docs.ts`, `generateBlogMeta`) from posts published at generation time (index first, then newest-first) and is git-ignored. It drives the Fumadocs page-tree with no hand-maintenance, so never edit it by hand.

## Configuration

The blog source and its frontmatter schema are configured in `web/next/source.config.ts`:

```ts
const blogSchema = pageSchema.extend({
  date: z
    .union([z.iso.date(), z.date()])
    .transform((value) => (value instanceof Date ? value.toISOString().slice(0, 10) : value)),
  draft: z.boolean().optional(),
  author: z.string().optional(),
  tags: z.array(z.string()).optional(),
})

export const blog = defineDocs({
  dir: "content/blog",
  docs: {
    schema: blogSchema,
    postprocess: { includeProcessedMarkdown: true },
  },
})
```
