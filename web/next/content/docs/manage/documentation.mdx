## Overview

Documentation content lives in `web/next/content/docs/` and is loaded through [Fumadocs](https://fumadocs.dev). The docs route uses Fumadocs for MDX loading, page metadata, page trees, and search UI, while the left sidebar remains a custom shadcn/ui implementation.

## Architecture

- `web/next/source.config.ts` defines the `docs` collection.
- `web/next/src/lib/source.ts` builds `docsSource` with `loader()` and `docs.toFumadocsSource()`.
- `web/next/src/app/(content)/docs/layout.tsx` scopes `RootProvider` to the docs route, not the global app root.
- `web/next/src/app/(content)/docs/layout.tsx` passes `tree={docsSource.getPageTree()}` into `DocsLayout`.
- `web/next/src/components/sidebar/docs/*` renders the custom docs sidebar.
- `web/next/src/lib/config.ts` stores the custom sidebar grouping and category labels.

The docs layout-level `RootProvider` is intentional. It keeps Fumadocs search state and hotkeys scoped to the content routes instead of the entire app. Because the app already uses `next-themes` globally in `web/next/src/app/providers.tsx`, the Fumadocs theme provider is disabled at the docs/blog layout level to avoid nesting a second `next-themes` provider.

## Content Structure

- **Location**: `web/next/content/docs/`
- **Format**: MDX files with frontmatter
- **Collection config**: `web/next/source.config.ts`
- **Ordering**: `web/next/content/docs/meta.json`

## Creating Documentation

1. Create a new `.mdx` file in `web/next/content/docs/`
2. Add frontmatter with `title` and `description`
3. Write content using MDX syntax
4. Add entry to `web/next/content/docs/meta.json`

## Configuration

Documentation source is configured in `web/next/source.config.ts`:

```ts
export const docs = defineDocs({
  dir: "content/docs",
})
```

The Fumadocs source loader lives in `web/next/src/lib/source.ts`:

```ts
import { loader } from "fumadocs-core/source"
import { docs } from "fumadocs-mdx:collections/server"

export const docsSource = loader({
  baseUrl: "/docs",
  source: docs.toFumadocsSource(),
})
```

Pages are listed in `web/next/content/docs/meta.json`. The sequence controls the Fumadocs page tree and the order used by docs navigation helpers:

## Search

The docs search API is implemented at `web/next/src/app/api/search/route.ts` with Fumadocs' built-in Orama integration:

```ts
import { createFromSource } from "fumadocs-core/search/server"
import { docsSource } from "@/lib/source"

export const { GET } = createFromSource(docsSource, {
  language: "english",
})
```

The visible search trigger in the docs sidebar lives at `web/next/src/components/sidebar/docs/search.tsx`. It opens the Fumadocs dialog through `useSearchContext()` instead of simulating a keyboard event. On mobile, the click handler closes the custom sidebar before opening search so the dialog does not appear behind the sheet.

The Next.js config still rewrites `/api/search` back to the app route:

```ts
{ source: "/api/search", destination: `${env.NEXT_PUBLIC_APP_URL}/api/search` }
```

### Keyboard Shortcut

Press `Cmd+K` (Mac) or `Ctrl+K` (Windows/Linux) to open the search dialog on the content routes. The hotkey and dialog state come from the route-scoped Fumadocs `RootProvider`.

## Navigation

Fumadocs still provides the canonical page tree for the docs route, but the rendered sidebar is intentionally custom. This matches current Fumadocs guidance after the old sidebar API removal and lets ZeroStarter keep its bespoke grouping under the "Manage" section without restructuring the content tree.

When you add or move a docs page:

1. Update `web/next/content/docs/meta.json` so Fumadocs page ordering stays correct.
2. Update `web/next/src/lib/config.ts` if the custom sidebar grouping should change.
