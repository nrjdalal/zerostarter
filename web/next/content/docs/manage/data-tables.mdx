Tables are built the way the [shadcn data-table guide](https://ui.shadcn.com/docs/components/base/data-table) recommends: there is no all-in-one `<DataTable data={...} />` prop machine. The page owns its [TanStack Table](https://tanstack.com/table) instance and composes the pieces in `web/next/src/components/data-table/`, so every table keeps the full headless API while sharing one look and one set of behaviors. Every table scrolls infinitely inside its own region with virtualized rows; there is no numbered pagination.

## The pieces

| Component                | File                 | Renders                                                                                                                                                                                        |
| ------------------------ | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DataTable`              | `data-table.tsx`     | The virtualized infinite-scroll region for your instance: sticky header, windowed rows, load-more on approach, a spinner while loading, an `Empty` fallback, and a selection/total status line |
| `DataTableCellText`      | `cell-text.tsx`      | Text-cell overflow: truncate (one line, ellipsis, tooltip only when actually cut) or wrap (multi-line; the measured virtual row grows)                                                         |
| `DataTableColumnHeader`  | `column-header.tsx`  | A sortable header: asc/desc (and hide, when allowed) behind a ghost-button dropdown                                                                                                            |
| `DataTableFacetedFilter` | `faceted-filter.tsx` | A multi-select value filter in a command palette, with per-value counts on client tables                                                                                                       |
| `DataTableToolbar`       | `toolbar.tsx`        | The search box (global filter), a children slot for filters, reset, and column visibility                                                                                                      |
| `DataTableViewOptions`   | `view-options.tsx`   | The column show/hide dropdown, labeled from `columnDef.meta.label`                                                                                                                             |

Two hooks carry the state:

- **`useDataTable`** (`hooks/use-data-table.ts`): the whole server-driven wiring in one call: URL state, the infinite query, and the manual-mode table instance. A page brings only what a generic hook cannot know: its columns, its `fetchPage`, its filter ids.
- **`useDataTableState`** (`hooks/use-data-table-state.ts`): just the URL state (`q`, `sort` as `column.asc`/`column.desc`, one array param per filter id via [nuqs](https://nuqs.dev)), pre-shaped for `useReactTable`. Client-side tables use this directly. There is no page state: any change resets the list. The `sort` param accepts a comma list for client tables; `useDataTable` disables multi-sort, since a server-driven fetch sorts by the first entry only.

A page's table pieces colocate with its route (`app/(console)/console/(platform)/users/components/data-columns.tsx` is the reference): typed `ColumnDef<Row>[]`, headers rendered through `DataTableColumnHeader`, a `meta: { label }` per hideable column so the view-options menu reads "Joined" instead of `createdAt`, an explicit `size` per column (virtualized rows position absolutely, so widths must be declared), with widths as a stable contract so content can never shift the layout: fixed columns hold exactly their size, `meta: { flex: true }` marks the one column whose size becomes a floor while it absorbs leftover width, `meta: { right: true }` docks a trailing group to the right edge when no flex column exists, and text cells render through `DataTableCellText` to either truncate (tooltip reveals the full value only when cut) or wrap.

## Column widths

Sizes come from `COLUMN_SIZES` (`components/data-table/column-sizes.ts`), in Tailwind spacing units (1 = `0.25rem`, so 12 = 48px at the default scale) rendered through `calc(var(--spacing) * n)`, so tables scale with the theme and user font-size. On a fixed column the size is exact (`width` + `shrink-0`); on the `meta.flex` column it is the floor (`min-width` + `flex-1`). The map is two levels: `global` holds the semantic archetypes (multiples of 3 units), and each area.table block maps its column ids onto them, so a columns file reads `COLUMN_SIZES.console.users.email` and never carries a number of its own. A deliberate deviation is a one-off number in the table block, not a new ad-hoc size at the call site. Names follow what the column says, never the backing field: the column headed Status keys as `status` (with `accessorKey: "banned"` underneath), not `banned`.

| Archetype | u   | Sized for                                      |
| --------- | --- | ---------------------------------------------- |
| `select`  | 12  | The row checkbox                               |
| `actions` | 6   | The icon-sm row-actions button                 |
| `role`    | 12  | A short role token like Admin or User          |
| `status`  | 12  | A short state word like Active or Banned       |
| `date`    | 18  | A compact date; content truncates              |
| `name`    | 64  | A plain text name                              |
| `email`   | 48  | A typical address; the usual `meta.flex` floor |

Tune an archetype, add one when a new kind of column appears, or add a table block there; columns files never carry raw numbers, and the map carries no entry nothing consumes. In local dev, columns render with alternating tints so the boxes stay visible while you tune.

## Server-driven tables

The console users table (`app/(console)/console/(platform)/users/components/data-table.tsx`) is the reference: sorting, search, and filters resolve on the API, and batches stream in on scroll. `useDataTable` bundles the [TanStack Query infinite pattern](https://tanstack.com/query/latest/docs/framework/react/guides/infinite-queries) (`useInfiniteQuery`, `getNextPageParam` against the response total, `keepPreviousData`, a deferred search term), so the page is a fetcher plus composition:

```tsx
const { error, isError, refetch, table, tableProps } = useDataTable({
  columns: usersColumns,
  enableRowSelection: true,
  fetchPage: fetchUsers, // (input: DataTablePageInput) => Promise<DataTablePage<Row>>
  filterIds: ["role"],
  getRowId: (row) => row.id,
  queryKey: "console-users",
})

<DataTableToolbar table={table} searchPlaceholder="Search users...">
  <DataTableFacetedFilter column={table.getColumn("role")} options={ROLE_OPTIONS} title="Role" />
</DataTableToolbar>
<DataTable {...tableProps} aria-label="Users" />
```

`fetchPage` receives `{ filters, page, perPage, search, sorting }` and returns `{ rows, total }`; the console maps it onto `GET /api/v1/admin/users`, whitelisting the sort column. The endpoint (`api/hono/src/routers/admin.ts`) escapes `LIKE` wildcards in the search, filters roles, pages with `page`/`perPage`, and is gated by `adminMiddleware` (see [API Conventions](/docs/manage/api-conventions)).

## Virtualized infinite scroll

`DataTable` follows [TanStack Table's virtualized-infinite-scrolling example](https://tanstack.com/table/v8/docs/framework/react/examples/virtualized-infinite-scrolling): the region is the scroll container, rows render as a [TanStack Virtual](https://tanstack.com/virtual) window (absolutely positioned inside a `tbody` sized to `getTotalSize()`, self-measured, `overscan: 5`), and `onLoadMore` fires within 500px of the bottom, on scroll and after every batch, so a not-yet-full region keeps loading. Semantic table tags stay but flip to grid/flex display, which is why columns declare explicit sizes. Sorting, search, or filter changes scroll back to the top.

### Filling the viewport

The table takes all available height below the page header. That needs a definite height at the top of the chain: the page passes `className="flex h-svh flex-col"` to `PageShell`, and everything between it and the region carries `flex-1 min-h-0` (the console Users page is the reference). Without a definite ancestor height the region grows with its content, the page scrolls instead of the table, and the always-near bottom loads every batch at once.

## Client-side tables

For a payload that fits in the browser, skip `useDataTable`: wire `useDataTableState` plus `defaultColumn: { minSize: 0 }` (sizes are spacing units; tanstack's pixel-minded default clamp would inflate them) and the row models (`getSortedRowModel`, `getFilteredRowModel`, and for facet counts `getFacetedRowModel` + `getFacetedUniqueValues`). All rows exist up front, the virtualizer windows them, and there is no `onLoadMore`. Set `globalFilterFn: "includesString"` so the toolbar search matches across columns, and give faceted columns `filterFn: "arrIncludesSome"`.

<Callout type="warn" title="TanStack Table v8 and the React Compiler">

`useReactTable` mutates one stable table instance during render, so compiler-memoized components comparing the instance identity never see sorting, selection, or row updates. Every file that reads a `table` or `column` instance (including `useDataTable`) carries the `"use no memo"` directive; keep it on new consumers or the table freezes one render behind.

</Callout>

## Accessibility

`DataTable`'s scroll region is named and focusable (`role="region"`, `tabIndex={0}`) so keyboard users can scroll it, the header stays sticky while scrolling, and sorted headers set `aria-sort`. The toolbar search is labeled.
