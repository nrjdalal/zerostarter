Tables are built the way the [shadcn data-table guide](https://ui.shadcn.com/docs/components/base/data-table) recommends: there is no all-in-one `<DataTable data={...} />` prop machine. The page owns its [TanStack Table](https://tanstack.com/table) instance (`useReactTable`) and composes the pieces in `web/next/src/components/data-table/`, so every table keeps the full headless API while sharing one look and one set of behaviors. Every table scrolls infinitely inside its own region; there is no numbered pagination.

## The pieces

| Component                | File                 | Renders                                                                                                                                                                  |
| ------------------------ | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DataTable`              | `table.tsx`          | The infinite-scroll region for your instance: sticky header, rows, a load-more sentinel, a spinner while loading, an `Empty` fallback, and a selection/total status line |
| `DataTableColumnHeader`  | `column-header.tsx`  | A sortable header: asc/desc (and hide, when allowed) behind a ghost-button dropdown                                                                                      |
| `DataTableFacetedFilter` | `faceted-filter.tsx` | A multi-select value filter in a command palette, with per-value counts on client tables                                                                                 |
| `DataTableToolbar`       | `toolbar.tsx`        | The search box (global filter), a children slot for filters, reset, and column visibility                                                                                |
| `DataTableViewOptions`   | `view-options.tsx`   | The column show/hide dropdown, labeled from `columnDef.meta.label`                                                                                                       |

Column definitions live next to the consumer (`components/console/users-columns.tsx` is the reference): typed `ColumnDef<Row>[]`, headers rendered through `DataTableColumnHeader`, and a `meta: { label }` per hideable column so the view-options menu reads "Joined" instead of `createdAt`.

## URL state

`useDataTableState` (`web/next/src/hooks/use-data-table-state.ts`) keeps the table state shareable and refresh-proof via [nuqs](https://nuqs.dev): `q` (search), `sort` (`column.asc`/`column.desc`), plus one array param per declared filter id (`role=admin,user`). It returns state and handlers shaped for `useReactTable`, so wiring is a spread. There is no page state: tables scroll infinitely, and any change to these values resets the list to a fresh first batch.

```tsx
const { sorting, globalFilter, columnFilters, ...handlers } = useDataTableState(["role"])
```

## Infinite scroll

`DataTable` is the scroll container: a focusable, named region with a sticky header and a sentinel row near the bottom. When the sentinel enters view (200px early), it calls `onLoadMore`; the observer is recreated whenever a batch lands, so it keeps loading until the region fills or the list ends. Wire it to [TanStack Query's infinite pattern](https://tanstack.com/query/latest/docs/framework/react/guides/infinite-queries), nothing hand-rolled:

```tsx
<DataTable
  aria-label="Users"
  table={table}
  hasMore={query.hasNextPage}
  isLoading={query.isPending}
  isLoadingMore={query.isFetchingNextPage}
  onLoadMore={() => query.fetchNextPage()}
  total={total}
/>
```

### Filling the viewport

The table takes all available height below the page header. That needs a definite height at the top of the chain: the page passes `className="flex h-svh flex-col"` to `PageShell`, and everything between it and the region carries `flex-1 min-h-0` (the console page is the reference). Without a definite ancestor height the region grows with its content, the page scrolls instead of the table, and the always-visible sentinel loads every batch at once.

## Server-driven tables

The console users table (`components/console/users-table.tsx`) is the reference for tables backed by an API. Sorting, search, and filters resolve on the server; batches stream in on scroll:

- `useInfiniteQuery` with `initialPageParam: 1` and a `getNextPageParam` that compares loaded rows against the response `total`; rows render from `pages.flatMap()`.
- `manualSorting` and `manualFiltering` on the table; the search term passes through `useDeferredValue` so fast typing batches requests, and `placeholderData: keepPreviousData` keeps rows on screen while a sort or filter refetches.
- The endpoint (`api/hono/src/routers/admin.ts`) whitelists sort columns, escapes `LIKE` wildcards in the search, filters roles, and pages with `page`/`perPage` (the client's batch size). It is gated by `adminMiddleware` (see [API Conventions](/docs/manage/api-conventions)).

## Client-side tables

For a payload that fits in the browser, drop the `manual*` flags and add the row models instead: `getSortedRowModel`, `getFilteredRowModel`, and (for facet counts) `getFacetedRowModel` + `getFacetedUniqueValues`. All rows render at once and the region simply scrolls; skip `onLoadMore` entirely. Set `globalFilterFn: "includesString"` so the toolbar search matches across columns, and give faceted columns `filterFn: "arrIncludesSome"`. The same `useDataTableState` hook drives both modes.

<Callout type="warn" title="TanStack Table v8 and the React Compiler">

`useReactTable` mutates one stable table instance during render, so compiler-memoized components comparing the instance identity never see sorting, selection, or row updates. Every component that reads a `table` or `column` instance carries the `"use no memo"` directive; keep it on new consumers or the table freezes one render behind.

</Callout>

## Accessibility

`DataTable`'s scroll region is named and focusable (`role="region"`, `tabIndex={0}`) so keyboard users can scroll it, the header stays sticky while scrolling, and sorted headers set `aria-sort`. The toolbar search is labeled and the sentinel row is `aria-hidden`.
