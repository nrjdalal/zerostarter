Tables are built the way the [shadcn data-table guide](https://ui.shadcn.com/docs/components/base/data-table) recommends: there is no all-in-one `<DataTable data={...} />` prop machine. The page owns its [TanStack Table](https://tanstack.com/table) instance (`useReactTable`) and composes the pieces in `web/next/src/components/data-table/`, so every table keeps the full headless API while sharing one look and one set of behaviors.

## The pieces

| Component                | File                 | Renders                                                                                                                                            |
| ------------------------ | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DataTable`              | `table.tsx`          | The table markup from your instance: header groups, rows, skeleton rows while loading, an `Empty` fallback, and a keyboard-focusable scroll region |
| `DataTableColumnHeader`  | `column-header.tsx`  | A sortable header: asc/desc (and hide, when allowed) behind a ghost-button dropdown                                                                |
| `DataTableFacetedFilter` | `faceted-filter.tsx` | A multi-select value filter in a command palette, with per-value counts on client tables                                                           |
| `DataTablePagination`    | `pagination.tsx`     | Page size, page position, first/prev/next/last, and the selection count when rows are selectable                                                   |
| `DataTableToolbar`       | `toolbar.tsx`        | The search box (global filter), a children slot for filters, reset, and column visibility                                                          |
| `DataTableViewOptions`   | `view-options.tsx`   | The column show/hide dropdown, labeled from `columnDef.meta.label`                                                                                 |

Column definitions live next to the consumer (`components/console/users-columns.tsx` is the reference): typed `ColumnDef<Row>[]`, headers rendered through `DataTableColumnHeader`, and a `meta: { label }` per hideable column so the view-options menu reads "Joined" instead of `createdAt`.

## URL state

`useDataTableState` (`web/next/src/hooks/use-data-table-state.ts`) keeps the whole table state shareable and refresh-proof via [nuqs](https://nuqs.dev): `page`, `perPage`, `q` (search), `sort` (`column.asc`/`column.desc`), plus one array param per declared filter id (`role=admin,user`). It returns state and handlers shaped for `useReactTable`, so wiring is a spread. Search, sort, and filter changes snap back to page 1.

```tsx
const { pagination, sorting, globalFilter, columnFilters, ...handlers } = useDataTableState([
  "role",
])
```

## Server-driven tables

The console users table (`components/console/users-table.tsx`) is the reference for tables backed by an API. The table runs in manual mode and the server does the work:

- `manualPagination`, `manualSorting`, `manualFiltering`, with `rowCount` from the response total; TanStack derives the page count.
- Data comes from `GET /api/v1/admin/users` through TanStack Query's paginated pattern: `placeholderData: keepPreviousData` keeps the previous page on screen while the next one loads.
- The search term passes through `useDeferredValue`, so fast typing batches requests.
- The endpoint (`api/hono/src/routers/admin.ts`) whitelists sort columns, escapes `LIKE` wildcards in the search, filters roles, and is gated by `adminMiddleware` (see [API Conventions](/docs/manage/api-conventions)).

## Client-side tables

For a payload that fits in the browser, drop the `manual*` flags and add the row models instead: `getSortedRowModel`, `getFilteredRowModel`, `getPaginationRowModel`, and (for facet counts) `getFacetedRowModel` + `getFacetedUniqueValues`. Set `globalFilterFn: "includesString"` so the toolbar search matches across columns, and give faceted columns `filterFn: "arrIncludesSome"`. The same `useDataTableState` hook drives both modes.

<Callout type="warn" title="TanStack Table v8 and the React Compiler">

`useReactTable` mutates one stable table instance during render, so compiler-memoized components comparing the instance identity never see sorting, pagination, or row updates. Every component that reads a `table` or `column` instance carries the `"use no memo"` directive; keep it on new consumers or the table freezes one render behind.

</Callout>

## Accessibility

`DataTable` wraps the table in a named, focusable scroll region (`role="region"`, `tabIndex={0}`) so keyboard users can reach horizontal overflow, and sets `aria-sort` on sorted headers. The toolbar search and the page-size select are labeled; the pagination buttons carry screen-reader names.
