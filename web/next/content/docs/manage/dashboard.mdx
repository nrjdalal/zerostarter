`/dashboard` is a signed-in page with nothing on it: the guard, the sidebar and the page frame are wired, and the console next door is the worked example you copy. Its heading says "Intentionally empty" because that is the design: auth, organizations and the API are in place, and this page is where your product begins.

The route group at `web/next/src/app/(protected)/` is the unit. Its `layout.tsx` guards everything beneath it and wraps every page in the shared sidebar, so a new page is one file under the group; the privileged `/console` area reuses the same chrome with two props flipped.

## When you need this

Reach for this page when you are about to build the first product page, or want to know what a signed-in user sees. For who can sign in and the ladder behind the Console link, see [Authentication](/docs/manage/authentication); for what the org switcher switches, see [Organizations](/docs/manage/organizations).

## The guard

`app/(protected)/layout.tsx` reads the session on the server with `auth.api.getSession({ disableCookieCache: true })` (`lib/auth/index.ts` wraps the API's `get-session` route) and redirects to `/` when there is none, so an unauthenticated request never renders the page. The same read decides whether the user menu shows a Console link: `reachesConsole` from `@packages/auth/access` is passed as the `canAccessConsole` prop, true for `member` and above who are not banned.

When the session carries no active organization, the layout restores the last one: the org switcher writes a `last-active-org_{userId}` cookie on every switch, and the layout posts that id to `/api/auth/organization/set-active` before rendering. A failed restore logs and renders anyway.

## The sidebar

The chrome is `SidebarShell` (`web/next/src/components/shell/sidebar-shell.tsx`), a shadcn `Sidebar` that collapses to an icon rail in the app and offcanvas inside the docs area, with three slots the layout fills:

| Slot            | Dashboard                                                                              | Console                                                    |
| --------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Header          | the brand linking to `homeHref` (`/dashboard`), the collapse trigger, the org switcher | the same, with a "Console" badge and `homeHref="/console"` |
| Content (`nav`) | empty: your navigation goes here                                                       | the console navigation                                     |
| Footer          | a Documentation link with the version (when `features.docs` is on), then the user menu | the user menu                                              |

Open or closed persists in a `sidebar_state` cookie, read on the server so the first paint matches. The org switcher (`components/dashboard/sidebar.tsx`) lists the user's organizations and offers a Create dialog whose slug comes from `slugify(name)`; the user menu (`components/shell/sidebar-user-menu.tsx`) carries avatar, name and email, a Home link to `/`, the Console cross-link, Feedback when `NEXT_PUBLIC_USERJOT_URL` is set, and Log out.

## Page content

A page wraps its content in `PageShell` (centering, width and padding through a `size` variant: `sm`, `md`, `lg`, `full`) and opens with `PageHeader`, which renders the page's one `h1` plus an optional description and actions row; both live in `components/shell/`. `app/(protected)/dashboard/page.tsx` is the whole pattern, and the `design` skill's "Spacing and page frame" section is the rule it follows.

## Common questions

**Why does every dashboard load read the session fresh?**

Because the Console link is drawn from it. The browser holds a session snapshot for the cookie cache window, so a cached read would leave someone just promoted to `member` with no way into the console they can already open; the gates on `/console` and the API read past the cache, and the dashboard matches them, at the cost of one session lookup on a round trip the layout makes anyway.

**How do I get back to the landing page?**

Home, the first item in the user menu. The sidebar brand links to `/dashboard` (and `/console` in the console) so a signed-in reader stays in the app, which leaves the menu as the one way out.

**Where did `DashboardShell` go?**

It is `PageShell`, and `DashboardHeader` is `PageHeader`, both under `components/shell/` since the components were regrouped by feature; the console wraps its pages in the same two, so a dashboard-prefixed name no longer fit.

## It's working if

- After the agent login (`AGENT_SIGNIN_ENABLED=true`, then **Login (agents)**), `/dashboard` renders the sidebar with your name in the footer and "Intentionally empty" under the heading.
- The user menu shows Console only for `member` and above; a `user` sees Home and Log out, plus Feedback when the URL is set.
- Collapse the sidebar and reload: it stays collapsed.
