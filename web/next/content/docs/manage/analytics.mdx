[PostHog](https://posthog.com) gives the web app product analytics, session replay and feature flags; a feedback link puts any URL in the docs sidebar and the dashboard user menu; Speed Insights reports real Core Web Vitals on Vercel. PostHog and the feedback link stay off until an environment variable is set, so out of the box neither runs. Speed Insights is the reverse: no key and no variable, it renders wherever `VERCEL` is set, and it goes away by deleting one line.

## When you need this

When you want to see what visitors do, hear from them, or measure what they experience, and want none of it running where you have not asked. For how the variables are declared, see [Environment Variables](/docs/manage/environment); for the rest a Vercel deploy turns on by itself, see [Deploy to Vercel](/docs/deployment/vercel).

## PostHog analytics

PostHog initializes in `web/next/instrumentation-client.ts`, Next.js's client-instrumentation entry, which runs once before the app hydrates. `posthog.init` sits behind a check on `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`, so with the token empty nothing initializes. With it set, `NEXT_PUBLIC_POSTHOG_HOST` picks the region: EU Cloud (`https://eu.i.posthog.com`) by default, `https://us.i.posthog.com` for US Cloud, or a self-hosted URL. Both are optional in `packages/env/src/web-next.ts`.

The `defaults` option in that call pins PostHog's defaults to a dated snapshot, pageview capture on history changes included, so there is no provider and no pageview component. The starter stops there: it never calls `capture` or `identify` and reads no flag. Pageviews begin the moment the token is set; every event beyond them is yours, from the shared singleton:

```ts
import posthog from "posthog-js"

posthog.capture("signup_clicked", { plan: "pro" })
posthog.identify(user.id, { email: user.email })
posthog.isFeatureEnabled("new-dashboard")
```

## Vercel Speed Insights

[Speed Insights](https://vercel.com/docs/speed-insights) reports Core Web Vitals from real visitors rather than a Lighthouse run's synthetic numbers. It needs no key because it reports only to the platform it runs on, and that is also why it is conditional: the beacon posts to `/_vercel/speed-insights/vitals`, a route only Vercel serves, so anywhere else it would fire requests that can never arrive. The root layout, `web/next/src/app/layout.tsx`, renders `{onVercel && <SpeedInsights />}`, where `onVercel` is `process.env.VERCEL === "1"`.

The platform injects `VERCEL`, which is why it appears in neither `packages/env` nor `.env.example`. The check stays in the layout, a server component, because Next inlines only `NEXT_PUBLIC_*` variables into client bundles: inside the client-side `SpeedInsights` the same check would read `undefined` and silently never render. Off Vercel the component is never rendered and the beacon never loads, though the static import still ships in the bundle, unexecuted. There is no enable step: the numbers appear under **Speed Insights** in the project dashboard once real visitors have been through.

<Callout type="warn" title="Previews count against your allocation">

Every deployment reports, previews included, and Vercel [meters Speed Insights by event](https://vercel.com/docs/speed-insights/limits-and-pricing) per team. Narrowing the gate to `VERCEL_ENV === "production"` drops PR previews but drops `canary` too, since canary deploys as a preview; to keep it, also test `VERCEL_GIT_COMMIT_REF === "canary"`, the way `.github/scripts/migrate-on-deploy.ts` picks its deploy branches.

</Callout>

To remove it, delete the import, the `onVercel` line and the render line, then drop `@vercel/speed-insights` from `web/next/package.json` and the root catalog.

## User feedback

One variable and no SDK: `NEXT_PUBLIC_USERJOT_URL`. The name points at [UserJot](https://userjot.com), but the value is any URL. Set it and a **Feedback** link appears in the docs sidebar footer beside the version label and in the dashboard user menu above **Log out**, each opening in a new tab. Leave it empty and neither renders; the footer still shows the version.

## Common questions

**Why `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN` and not `_KEY`?**

It is the name PostHog's docs use; the starter renamed it from `NEXT_PUBLIC_POSTHOG_KEY` when it adopted PostHog's current App Router setup and dropped the provider. The token is optional, so a deployment still setting the old name gets no error and no analytics.

**Where did the UserJot widget go?**

The starter once injected UserJot's SDK as a floating widget keyed by `NEXT_PUBLIC_USERJOT_ID`. It became a plain link so no third-party script loads on every page and the destination can be any form. The ID variable is gone; set the URL.

## It's working if

- With the token set, the first page load sends a request to your PostHog host, visible in the network tab; with it empty, none.
- On Vercel the page requests `/_vercel/speed-insights/script.js`; on Docker nothing under `/_vercel/` is requested.
- With `NEXT_PUBLIC_USERJOT_URL` set, **Feedback** shows in the docs sidebar footer and the user menu.
