[PostHog](https://posthog.com) gives the web app product analytics, session replay and feature flags; a feedback link puts any URL in the docs sidebar and the dashboard user menu; Speed Insights reports real Core Web Vitals on Vercel. PostHog and the feedback link stay off until an environment variable is set, so out of the box neither runs. Speed Insights is the reverse: no key and no variable, it renders wherever `VERCEL` is set until you remove it.

## When you need this

When you want to see what visitors do, hear from them, or measure what they experience, and want none of it running where you have not asked. For how the variables are declared, see [Environment Variables](/docs/manage/environment); for the rest a Vercel deploy turns on by itself, see [Deploy to Vercel](/docs/deployment/vercel).

## PostHog analytics

PostHog initializes in `web/next/instrumentation-client.ts`, Next.js's client-instrumentation entry, which runs once before the app hydrates. `posthog.init` sits behind a check on `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`, so with the token empty nothing initializes. With it set, `NEXT_PUBLIC_POSTHOG_HOST` picks the region: EU Cloud (`https://eu.i.posthog.com`) by default, `https://us.i.posthog.com` for US Cloud, or a self-hosted URL. Both are optional in `packages/env/src/web-next.ts`.

The `defaults` option in that call pins PostHog's defaults to a dated snapshot, pageview capture on history changes included, so there is no provider and no pageview component. The starter never calls `capture` or `identify` and reads no flag, but the call passes nothing beyond `api_host` and `defaults`, so PostHog's own defaults run the moment the token is set: pageviews, page leaves, autocapture of clicks and form submissions, and session recording whenever replay is on in your PostHog project. That includes the console pages, which render people's email addresses, so before setting the token on an install with real users, decide whether to add `autocapture: false` and `disable_session_recording: true` to that `posthog.init` call. Every named event and identity is yours, from the shared singleton:

```ts
import posthog from "posthog-js"

posthog.capture("signup_clicked", { plan: "pro" })
posthog.identify(user.id, { email: user.email })
posthog.isFeatureEnabled("new-dashboard")
```

## Vercel Speed Insights

[Speed Insights](https://vercel.com/docs/speed-insights) reports Core Web Vitals from real visitors rather than a Lighthouse run's synthetic numbers. It needs no key because it reports only to the platform it runs on, and that is also why it is conditional: the beacon posts to `/_vercel/speed-insights/vitals` by default, a route only Vercel serves, so anywhere else it would fire requests that can never arrive. The root layout, `web/next/src/app/layout.tsx`, renders `{onVercel && <SpeedInsights />}`, where `onVercel` is `process.env.VERCEL === "1"`.

`VERCEL` is injected by the platform, so it sits outside the schema the way [Environment Variables](/docs/manage/environment) describes. The check stays in the layout, a server component, because Next inlines only `NEXT_PUBLIC_*` variables into client bundles: inside the client-side `SpeedInsights` the same check would read `undefined` and silently never render. Off Vercel the component is never rendered and the beacon never loads, though the static import still ships in the bundle, unexecuted. There is no enable step: the numbers appear under **Speed Insights** in the project dashboard once real visitors have been through.

<Callout type="warn" title="Previews count against your allocation">

Every deployment reports, previews included, and Vercel [meters Speed Insights by event](https://vercel.com/docs/speed-insights/limits-and-pricing) per team. Narrowing the gate to `VERCEL_ENV === "production"` drops PR previews but drops `canary` too, since `canary` deploys as a preview while `main` is the project's Production Branch; to keep it, also test `VERCEL_GIT_COMMIT_REF === "canary"`, the way `.github/scripts/migrate-on-deploy.ts` picks its deploy branches.

</Callout>

To remove it, delete the import, the `onVercel` line and the render line, then drop `@vercel/speed-insights` from `web/next/package.json` and the root catalog.

## User feedback

One variable and no SDK: `NEXT_PUBLIC_USERJOT_URL`. The name points at [UserJot](https://userjot.com), but the value is any URL. Set it and a **Feedback** link appears in the docs sidebar footer beside the version label and in the dashboard user menu above **Log out**, each opening in a new tab. Leave it empty and neither renders; the footer still shows the version.

## Common questions

**Why `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN` and not `_KEY`?**

It is the name PostHog's docs use; the starter renamed it from `NEXT_PUBLIC_POSTHOG_KEY`. The token is optional, so a deployment still setting the old name gets no error and no analytics.

**Where did the UserJot widget go?**

It is the **Feedback** link now: set `NEXT_PUBLIC_USERJOT_URL`, since `NEXT_PUBLIC_USERJOT_ID` and the floating widget it keyed are gone. A plain link loads no third-party script on every page, and its destination can be any form.

## It's working if

- With the token set, the first page load sends a request to your PostHog host, visible in the network tab; with it empty, none.
- On Vercel the page requests `/_vercel/speed-insights/script.js` by default; on Docker nothing under `/_vercel/` is requested.
- With `NEXT_PUBLIC_USERJOT_URL` set, **Feedback** shows in the docs sidebar footer and the user menu.
