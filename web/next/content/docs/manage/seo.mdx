A fresh deploy is indexable and unfurls a rendered preview without configuration; three routes under `web/next/src/app/` do it, and the publish gate they share means nothing unpublished leaks. `robots.ts` serves `/robots.txt`, `sitemap.ts` serves `/sitemap.xml`, and `og/*` renders the Open Graph images, all driven by your content and `NEXT_PUBLIC_APP_URL`, with the OG routes reading `packages/config/src/site.ts` for the name and tagline.

The gate is `contentSource` in `web/next/src/lib/content.ts`: a kind whose feature is off behaves as an empty collection, and the blog kind hides drafts and scheduled posts, so a sitemap entry or a preview exists only for a page that is live.

## When you need this

Reach for this page when a shared link shows the wrong preview, a page is missing from the sitemap, or a crawler is indexing something it should not. For what makes a post public in the first place, see [Content](/docs/manage/content); for where `NEXT_PUBLIC_APP_URL` is set, see [Environment Variables](/docs/manage/environment).

## Indexable by default

No public page carries a `noindex` and nothing sets an `X-Robots-Tag` header, so crawlers index the site out of the box; the console layout alone sets `robots: { index: false, follow: false }` in its metadata. `robots.ts` allows `/` (every public page, the OG images included), disallows `/api/`, `/console/` and `/dashboard/`, and points at `${baseUrl}/sitemap.xml`, where `baseUrl` is `NEXT_PUBLIC_APP_URL`.

## Sitemap

`sitemap.ts` discovers pages from the collections instead of a hand-kept list: the home route, every page the docs kind returns, and the published blog posts. It is `force-static` with `revalidate = 60`, so it regenerates at most once a minute, and its URLs are sorted alphabetically.

Each entry's `changeFrequency` and `priority` are per type, set in `sitemap.ts`. Home and docs entries set `lastModified` to the time of the regeneration that produced them (`new Date()`); a blog entry uses `updatedAt` when present, else `publishedAt`. The `/blog` index is absent because the published list holds posts only. Turn the docs or blog [feature](/docs/manage/features) off and its entries drop.

## OG images

Each content kind has its own Open Graph route, rendered with [takumi](https://takumi.kane.tw):

| Route                              | Preview                    |
| ---------------------------------- | -------------------------- |
| `/og/blog/[[...slug]]`             | Blog posts                 |
| `/og/docs/[[...slug]]`             | Docs pages                 |
| `/og/home`                         | Landing page               |
| `/og?section=&title=&description=` | Generic, from query params |

The docs route is prerendered at build (`force-static` with `generateStaticParams`); the blog route prebuilds the published posts and revalidates every 60 seconds, so a scheduled post gets its preview without a rebuild; `/og/home` is static and the generic `/og` is `force-dynamic`. `generatePageMetadata()` in `web/next/src/lib/fumadocs.tsx` wires each image into the page's metadata, and omits it for a console docs page rather than link a route that does not exist.

Every route renders through `renderOgImage` in `web/next/src/lib/og-image.tsx`: a 1200x630 PNG with a section label, a title whose size steps down as it grows, and a description, in `system-ui`, since no font ships. The response carries a one-year immutable `Cache-Control`. A render failure during a production build throws, failing the build rather than shipping a broken image; at runtime it logs and returns a 500.

To add a kind, copy `web/next/src/app/og/blog/[[...slug]]/route.tsx`, register the kind in the `REGISTRY` in `web/next/src/lib/content.ts` with `og: true`, and keep `revalidate` when the kind is time-gated. `getPageOr404` and `params()` apply the kind's publish policy, so the route never hand-filters.

To preview one, open its route while the dev server runs: `/og/home`, `/og/docs/manage/seo`, or `/og?section=Demo&title=Hello&description=World` to tweak the text live; the route reads `section`, `title` and `description`, the order the image draws them, top to bottom. To ship a hand-made landing image instead, drop a `public/og/home.png` in place and the home metadata points at it.

<Callout type="warn" title="Keep the takumi binary traced for /og on Vercel">

Vercel traces `/og` into its own function, and takumi's core is a native binary loaded dynamically, so tracing cannot follow the import. `next.config.ts` force-includes the matching-libc `@takumi-rs/core` binary for `/og` through `outputFileTracingIncludes`; remove it and `/og` returns a 500 at runtime. It looks removable because it is redundant in Docker standalone, where the whole `node_modules` ships in one image.

</Callout>

## Common questions

**Why `/og` and not `/api/og`, and why the `?t=` on every image URL?**

`robots.txt` disallows `/api/`, and an unfurler that honors it would never fetch the image, so the routes live at `/og`. The timestamp is the cache-bust: the image is cached for a year, so without a query string that changes per deploy a scraper keeps the old picture. `generatePageMetadata` builds the URL once, slug first and timestamp last.

## It's working if

- `/robots.txt` lists `Disallow: /api/`, `/console/` and `/dashboard/`, and a `Sitemap:` line with your app URL.
- `/og/home` renders a 1200x630 PNG, and `/og?section=Demo&title=Hello&description=World` renders those words.
- `/sitemap.xml` omits a post dated tomorrow and lists it within about a minute once the date passes.
- A docs page's `og:image` meta tag ends in `?t=` and a number.
