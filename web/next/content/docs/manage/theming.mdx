You restyle ZeroStarter by editing tokens, not components. Colors, fonts and radii are CSS custom properties in `web/next/src/app/globals.css`, Tailwind v4's `@theme inline` block binds each to a utility class, and every component reaches for the utility, never a raw color (the `design` skill's Color rule), so one edit flows to every surface in both themes.

That file is also one the shadcn sync re-scaffolds: `bun run shadcn:update` runs `shadcn init` over `globals.css`, so a token the registry writes (`--background`, `--font-heading`, `--font-sans`, `--sidebar` and the rest) takes the registry's value back, the overrides the `shadcn-sync` skill lists under Guards then restore their lines, and a token the registry does not write (`--font-mono`, `--success`) survives. A registry token changed without a guard holds until the next sync, then reverts.

## When you need this

Reach for this page when you are restyling: a brand color, the sans, a radius, the dark palette. A new component or a layout decision is the `design` skill ([AI Skills](/docs/resources/ai-skills)); a change to a `ui/*` primitive is a `shadcn-sync` override.

## Dark mode

[next-themes](https://github.com/pacocoursey/next-themes) toggles a `.dark` class on `<html>` and follows the OS until the reader picks a side; `InnerProvider` in `web/next/src/app/providers.tsx` configures it, and `@custom-variant dark (&:is(.dark *))` in `globals.css` makes that class what `dark:` keys on. The `ModeToggle` (`web/next/src/components/common/mode-toggle.tsx`) cycles three states: from `system` to the opposite of the OS preference, from a choice that matches the OS to its opposite, and from a choice that diverges from the OS back to `system`.

## Tokens

Colors live in the `:root` and `.dark` blocks as [OKLCH](https://oklch.com) values (`--background` is `oklch(1 0 0)` in light and `oklch(0.145 0 0)` in dark), and since OKLCH's first channel is lightness, a dark variant is often the same hue with L flipped. The `@theme inline` block maps `--color-background` onto `var(--background)` and its siblings, which is what makes `bg-background` and `text-success` resolve; a new token is one line in each block and one in the map.

## Fonts

Fonts are self-hosted through `next/font/local` (`web/next/src/lib/fonts.ts`, woff2 in `web/next/src/fonts/`), each a variable that `globals.css` binds to a role: `--font-sans` is DM Sans through `--font-dm-sans`, `--font-mono` is JetBrains Mono through `--font-jetbrains-mono`, and `--font-heading` reuses the sans. That last role is read by the shadcn titles under `components/ui/` (`rg -l font-heading web/next/src/components/ui` lists every reader), not by page headings, which take the sans through `html`. It is a registry token too, so pointing it at a separate face reverts on the next sync unless that line becomes a guard in `.github/scripts/shadcn-customize.ts`, the `shadcn-sync` skill's route for an override. Adding, swapping or removing a face is the `fonts` skill, which also moves the two scripts that name the sans.

## Common questions

**Why did my sidebar color revert?**

Because `bun run shadcn:update` rewrote `globals.css`. `--sidebar` is a registry token, hardcoded in light and dark by shadcn's template, so the sync resets it and the guard in `shadcn-customize.ts` puts back `var(--background)`, not your value. Your own override goes in that script the same way; the `shadcn-sync` skill's Guards list is the complete set.

**Why do Caveat and Lora live in a different file?**

Because preload follows the import graph. The root layout imports `lib/fonts.ts`, so every face there preloads on every page; Caveat and Lora render only on `/hire` and `/resume`, so they sit in the fork-excluded `web/next/src/lib/marketing/fonts.ts` (`--font-caveat`, `--font-lora`, applied by `.className`), which only those two pages import.

## It's working if

- A token edited in both `:root` and `.dark` shows on the next render in both themes, and the `ModeToggle` flips between them.
- `bun run shadcn:update` on a clean tree leaves a registry-token edit in place once its guard is in `shadcn-customize.ts`; without one, `git diff` shows the registry value back.
