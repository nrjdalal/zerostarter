An LLM doesn't browse; it ingests. HTML docs and the interactive [Scalar reference](/docs/getting-started/type-safe-api) at `/api/docs` are built for a human clicking around; `/llms.txt` hands an agent the same knowledge as flat markdown it can read top to bottom, with no JavaScript and no navigation to crawl.

Both files are generated at build from the same sources as the pages, so they cannot list a page that does not exist, and a feature turned off drops its pages from them in the same build.

## When you need this

Reach for this page when you are pointing an agent at the project, or when the index and the site seem to disagree. For where the pages come from, see [Content](/docs/manage/content); for the loop an agent runs with this context, see [Working with Agents](/docs/getting-started/working-with-agents).

## Two files and an alias

| Route                                     | What it holds                                                                                                                                                                                                                                                                                            |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/llms.txt`                               | the index: every docs page in sidebar order, each linked as its `.md` alias with its description, then a link to the blog                                                                                                                                                                                |
| `/llms-full.txt`                          | everything in one file: the site name and description, `llmsFullPreamble` from `packages/config/src/site.ts` (the canonical starter's layout, import map, stack and conventions; a fork's starts empty, since `init` regenerates that file), then every docs page and published post, `---` between them |
| any docs or blog URL plus `.md` or `.txt` | that page as markdown, a docs page with a footer pointing back to `/llms.txt`; `/docs.md` is the docs root page and `/blog.md` the blog index                                                                                                                                                            |

The aliases are rewrites in `web/next/next.config.ts` onto the `/llms.txt/docs/...` and `/llms.txt/blog/...` routes. In development, `curl "$(bunx portless get zerostarter)/llms-full.txt"` hands an agent the docs, the published posts and the preamble as one file before it writes a line, which is how the `codebase-map` skill orients.

## How they're generated

Two `force-static` route handlers under `web/next/src/app/(llms.txt)/`, revalidated every 60 seconds, read the Fumadocs collections through the same `contentSource` the pages use. Docs sort with `sortByMeta` against `content/docs/meta.json`, derived from `web/next/docs.config.ts`, so the index, the full file and the sidebar agree; the blog lists published posts, newest first. Console docs are a collection no public route reads, so they are out by construction.

Page bodies come from `getLLMText` in `web/next/src/lib/llms.ts`. Every collection in `web/next/source.config.ts` sets `includeProcessedMarkdown: true`, so a page's rendered markdown is there to read; `decodeHTML` undoes Fumadocs' HTML escaping, and a `# [title](url)` heading links back to the live page.

Docs and blog are [features](/docs/manage/features): turn one off and its pages, its index and its aliases drop from both files, so neither can point at a page that 404s.

## Common questions

**Why is `/llms.txt` in a different order from the sidebar?**

Both routes share `sortByMeta`, so the docs follow `docs.config.ts`, and a page at the tail is one that file does not list. The web build runs `bun .github/scripts/docs.ts --strict`, which fails on that drift ([Content](/docs/manage/content#docs-the-config-is-the-source-of-truth)); in dev the tail means a stale `meta.json`, and `bun .github/scripts/docs.ts` regenerates it.

**Why is `/docs.md` a page while `/blog.md` is a list?**

The docs have a root page, the introduction at `/docs`, so its alias serves that page. The blog's root is a listing with no page of its own, so its alias serves the blog index, the one `/llms.txt` links.

## It's working if

- `/llms.txt` lists the docs pages in the sidebar's order, the introduction first.
- `/llms-full.txt` opens with a heading ending in `LLM Context File`, the site description as a quote, then the first docs page after a `---`; in the canonical starter the preamble sits between them, opening with `## Instructions for AI Assistants`.
- `curl -s -o /dev/null -w "%{content_type}" "$WEB/docs/manage/llms-txt.md"`, with `$WEB` the web URL (`bunx portless get zerostarter` in development), prints `text/markdown; charset=utf-8`, and the body ends with the footer pointing at `/llms.txt`.
