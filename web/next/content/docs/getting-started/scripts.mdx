Every script you run is `bun run <name>` from the root `package.json`, and most call a file in one of two places. `packages/scripts/src/` is a workspace package, so `turbo prune` carries it and its declared dependencies into the Docker build: a new build or tooling script lands there, with its imports declared on that package. `.github/scripts/` reaches the image only through an extra `COPY` in each Dockerfile and borrows the root dev dependencies.

## When you need this

Reach for this page to look up what a script does and when it runs, or to place a new one. The `dev` skill holds the dev loop; [Code Quality](/docs/manage/code-quality) says what the hooks and CI run.

## Check and ship

### Build and release

| Script                    | What it does                                                                                                                      |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `bun run build`           | Build every workspace with Turbo and print each app's output size; the pre-commit hook's build                                    |
| `bun run release:version` | Print the release window's version decision as JSON, writing nothing and needing no network; `--write` moves `package.json` to it |
| `bun run start`           | Serve the production builds: the web's standalone server and the api bundle                                                       |

The release workflows run `release:version`; by hand it previews ([Releases](/docs/manage/release)).

### Quality

| Script                 | What it does                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| `bun run check-types`  | `tsc --noEmit` in every workspace, then over `.github/scripts`, then once per `tests/**/tsconfig.json` |
| `bun run format`       | Oxfmt, writing fixes                                                                                   |
| `bun run format:check` | Oxfmt, report only                                                                                     |
| `bun run lint`         | Oxlint over the tree                                                                                   |
| `bun run test`         | Build `packages/*`, regenerate the data-table font metrics, then run the suite under `tests/`          |
| `bun run test:e2e`     | Every `*.e2e.test.ts` against a stack already running on the compose ports                             |

[Code Quality](/docs/manage/code-quality#the-gates-in-order) says which of these the hooks and the pull request run. `tests/` belongs to the canonical starter, so in a fork `test` and `test:e2e` no-op. `test` builds the shared packages first because a test imports one through its `exports`, which point at `dist`. The end-to-end suite skips itself when no stack is named, so `test` stays green without one and no CI job runs it; the `docker-test` skill runs it against the images.

## Develop

### Console

| Script                                                       | What it does                                                                                                          |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `bun run console:roles <grant\|revoke\|list> [email] [role]` | Grant, list or revoke a user's rung on the [console role ladder](/docs/manage/authentication#the-console-role-ladder) |

It writes to the database `POSTGRES_URL` names. The usage header of `.github/scripts/console-roles.ts` holds each action and the defaults it takes.

### Database

| Script                | What it does                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------- |
| `bun run auth:schema` | Regenerate `packages/db/src/schema/auth.ts` from `packages/auth/src/schema.ts`; `--check` only compares |
| `bun run db:generate` | Generate a migration from schema changes                                                                |
| `bun run db:migrate`  | Apply pending migrations                                                                                |
| `bun run db:studio`   | Open Drizzle Studio                                                                                     |

Each `db:*` script builds `@packages/env` first, which `drizzle.config.ts` imports built, then runs Drizzle Kit in `packages/db`. [Database](/docs/manage/database) holds the loop and the `db-migration` skill the steps.

### Dev loop

| Script             | What it does                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `bun run clean`    | Remove build output, caches, generated files and every `node_modules`; `bun install` again afterward                      |
| `bun run dev`      | Both apps on named `.localhost` URLs through portless, branch-prefixed in a worktree; `PORTLESS=0` uses `3000` and `4000` |
| `bun run devtools` | The Turborepo package graph in the browser                                                                                |

### shadcn

| Script                  | What it does                                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------------------------- |
| `bun run shadcn:update` | Re-scaffold every shadcn/ui component from the registry, re-apply the local overrides, format, then `bun i` |

<Callout type="warn" title="The sync wipes web/next/src/components/ui">

A hand edit there is lost on the next sync; a durable customization goes in `.github/scripts/shadcn-customize.ts`, which the sync re-applies (the `shadcn-sync` skill).

</Callout>

Lifecycle scripts, and the files builds, hooks and workflows call by path:

| Script                                            | When                                             | What it does                                                                     |
| ------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------- |
| `.github/scripts/build-sizes.ts`                  | after `build`; the release, with `--graph`       | the size table; `.github/assets/graph-build.svg`                                 |
| `.github/scripts/changelog-manager.ts`            | the release                                      | the changelog's compare links and contributor names                              |
| `.github/scripts/compress-images.ts`              | the web build                                    | compress `web/next/public` in place                                              |
| `.github/scripts/docs.ts`                         | the web build (`--strict`), `check-types`, `dev` | `meta.json` and each page's frontmatter from `docs.config.ts`                    |
| `.github/scripts/ensure-remote-branches.ts`       | the pre-push hook                                | seed `main` on a fresh GitHub remote                                             |
| `.github/scripts/migrate-on-deploy.ts`            | the api's Vercel build                           | `db:migrate`, on production and `canary` deploys only                            |
| `.github/scripts/portless.ts`                     | `dev`                                            | each app's portless URLs, injected before its dev command                        |
| `.github/scripts/skills-manager.ts`               | the pre-commit hook, when a skill is staged      | the `AGENTS.md` skills tables                                                    |
| `packages/scripts/src/data-table-metrics.ts`      | the web build, `check-types`, `dev`, `test`      | the header font's metrics, into `.generated/`                                    |
| `packages/scripts/src/generate-env.ts`            | the auth and web builds                          | the app host's breakdown (cookie scope, private-host signal), into `.generated/` |
| `postinstall` (`.github/scripts/deps-manager.ts`) | `bun install`; a staged `package.json`           | sort the `catalog`, move a dependency into it, caret every exact or tilde pin    |
| `prepare`                                         | `bun install`                                    | install the Lefthook hooks                                                       |

The pull-request workflow, Vercel and the Dockerfiles install with `--ignore-scripts`, so neither lifecycle script runs there.

## Common questions

**Why did `postinstall` rewrite the version I pinned?**

Every root `catalog` entry is a caret range, and the dependency manager restores one on every install with no opt-out: a deliberate pin means changing that rule in `deps-manager.ts` and recording why (in the canonical starter, `.github/notes/dependencies.md`). A range it cannot convert is reported for a manual fix.

**Why does `release:version` stop with `v* tags exist but none is reachable from HEAD`?**

The clone holds `v*` tags that HEAD's history does not reach, usually because it is shallow: run `git fetch --unshallow --tags`, then run it again. The message's own advice falls short there, since fetching the tags into a shallow clone leaves the history between HEAD and them missing. A clone with no tags at all does not stop: it computes from `v0.0.0`, so fetch the tags before trusting its number.

## It's working if

- `bun run release:version` prints one JSON line holding `next`, and `git status` stays clean.
- `bun run build` ends in a size table with `@api/hono` and `@web/next` rows.
- `bun run test` passes with no stack running, the end-to-end files skipped.
