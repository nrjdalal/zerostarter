[Infisical](https://infisical.com) is an optional source for the root `.env`: a shared vault holds the secrets and every teammate pulls the same file with one command. Nothing in the repo reads Infisical at runtime; `@packages/env/*` validates whatever `.env` holds, wherever it came from, so a hand-written file behaves identically.

## When you need this

When a team is sharing and rotating secrets and wants one place to do it. Working alone, copy `.env.example` to `.env` and skip this page; [Environment Variables](/docs/manage/environment) says what each value means.

## Prerequisites

An Infisical workspace holding the keys `.env.example` names, and the CLI, installed the way Infisical documents: `npm install -g @infisical/cli`, or `brew install infisical/get-cli/infisical` on macOS.

## How the repo wires it

`.infisical.json` at the root links the checkout to a project: a `workspaceId`, a `defaultEnvironment` (empty, so the CLI falls back to `dev`), a `gitBranchToEnvironmentMapping` (unset), and no secret, which is why it is safe to commit. The canonical starter commits its own; the file is fork-excluded, so a fork links its checkout itself:

```sh
infisical login   # opens the browser
infisical init    # writes .infisical.json with your project's id
```

From then on one command writes the `.env` that `@packages/env/*` reads:

```sh
infisical export --env=dev --output-file=./.env
```

`--env` is one of your project's environment slugs (`dev`, `staging` and `prod` on a fresh project); omitted, the CLI reads `defaultEnvironment`, then falls back to `dev`. Re-run the export whenever a secret changes: Infisical is the source, `.env` the local artifact it lands in. Machine identities for CI and the full flag list are in the [CLI reference](https://infisical.com/docs/cli/overview).

## It's working if

- `infisical export` with no output file prints a single-quoted `KEY='value'` line for each key `.env.example` names.
- After the export, `bun run dev` starts without an environment validation error.
