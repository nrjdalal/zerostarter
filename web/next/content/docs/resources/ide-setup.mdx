ZeroStarter ships a `.vscode/` folder so the editor lints and formats with the [Oxc](https://oxc.rs) toolchain, one Rust tool in place of ESLint and Prettier. The editor runs the same `oxlint` and `oxfmt` binaries the hooks and CI run, so what you see on save is what the commit will enforce.

## When you need this

The first time you open the repo in VS Code or Cursor, or when a file looks fine in the editor and the pre-commit hook rewrites it anyway.

## VS Code

Two files do all of it: `.vscode/extensions.json` recommends one extension, `oxc.oxc-vscode`, and `.vscode/settings.json` makes it the default formatter and turns on format-on-save. Install the [Oxc extension](https://marketplace.visualstudio.com/items?itemName=oxc.oxc-vscode) and it lints with Oxlint and formats with Oxfmt inline; lint-staged runs the same binaries over the staged files on every commit, which catches an editor without it.

The extension reads the root `.oxlintrc.jsonc` and `.oxfmtrc.jsonc`, the same config the hooks and CI read, so the editor and the CLI cannot disagree; [Code Quality](/docs/manage/code-quality#the-gates-in-order) says what each sets.

## Cursor

[Cursor](https://cursor.com) reads the same `.vscode/` folder, so the extension and format-on-save work with no extra setup.

## It's working if

- A saved `.ts` file loses its semicolons and its imports come out sorted.
- A file under `.agents/` stays exactly as you wrote it, since `.oxfmtrc.jsonc` leaves `.agents/**` out of formatting.
