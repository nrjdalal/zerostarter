ZeroStarter ships `.vscode/` config so your editor lints with the same [Oxc](https://oxc.rs) toolchain the CLI and git hooks use: one Rust tool in place of ESLint, fast enough to run on every save.

## VS Code

Open the repo and VS Code recommends one extension, from `.vscode/extensions.json`:

```json
{
  "recommendations": ["oxc.oxc-vscode"]
}
```

Install the [Oxc extension](https://marketplace.visualstudio.com/items?itemName=oxc.oxc-vscode) and it lints (Oxlint) inline. `.vscode/settings.json` turns format on save off, since [`bun fmt`](https://bun.com/docs/format) formats each staged file at commit and has no editor integration:

```json
{
  "editor.formatOnSave": false
}
```

The extension reads the project's root lint config, so the editor and the CLI can never disagree:

- `.oxlintrc.jsonc`: lint rules.
- `bunfig.toml`'s `[fmt]` section, read by `bun fmt`: formatting like oxfmt: no semicolons, sorted imports, Tailwind classes in the theme's order, package.json scripts A to Z. It ignores `.agents/**`, so the AI skill docs are left untouched.

## Cursor

[Cursor](https://cursor.com) reads the same `.vscode/` config, so the extension works with no extra setup.

## From the terminal

No editor integration required. The same checks run from the shell, and again on commit:

```bash
bun run format          # format the tree with bun fmt
bun run format:check    # check formatting without writing
bun run format:changed  # check only the files that differ from canary
bun run lint            # lint the tree with Oxlint
```
