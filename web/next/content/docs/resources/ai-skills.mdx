## Overview

ZeroStarter ships a `.agents/skills/` directory of structured instructions for AI coding assistants (Claude Code, Cursor, Copilot, and any other runtime that reads the emerging `AGENTS.md` / `SKILL.md` conventions). Each skill is a markdown file with YAML frontmatter — human-readable and machine-parseable.

A single physical tree serves every runtime: `.agents/skills/` is the source of truth, and `.claude/skills` + `.github/skills` are symlinks into it.

## Shipped skills

### `docs`

**Location:** `.agents/skills/docs/SKILL.md`

The one skill this template needs to keep on its own: a workflow guide for reading the Fumadocs site (`web/next/content/docs/**`) and keeping every sync-point coherent when pages or features change.

**Triggers:** whenever an agent needs to learn how something in this template works, and whenever it adds / removes / renames / reorders a doc page or ships a feature whose behavior is described in docs.

**What it enforces:**

- **Reading:** use the `<site>/llms.txt`, `<site>/llms-full.txt`, and `.md`-suffix endpoints served from `web/next/src/app/(llms.txt)/**` instead of re-deriving behavior from source.
- **Tier 1 sync (manual, silently breaks):** `web/next/content/docs/meta.json`, the `config.sidebar` tree in `web/next/src/lib/config.ts`, and the Quick Links in `web/next/content/docs/index.mdx` (plus blog equivalents).
- **Tier 2 (auto, depends on Tier 1):** `llms.txt` / `llms-full.txt` routes, sitemap, OG, search.
- **Tier 3 (only on path / title changes):** root `README.md` links, `web/next/next.config.ts` rewrites, `web/next/source.config.ts`, and this page.
- **MDX rules:** required `title` / `description` frontmatter, fumadocs-mdx components, absolute `/docs/<slug>` cross-links.
- **Checklists** for adding / renaming / deleting pages and for changing feature behavior.

## Adding more skills

The template intentionally ships with just the `docs` skill. Reach for a new skill only when you notice yourself repeating the **same multi-step instructions** to an agent across sessions — if the answer is "read the docs", put it in the docs instead.

### Skill structure

```
.agents/skills/
└── <skill-name>/
    └── SKILL.md
```

### SKILL.md format

```markdown
---
name: skill-name
description: One sentence. What it does AND when the agent should load it. Runtimes match on this to decide when to inject the skill.
---

# Skill Title

Body with the actual procedure, rules, checklists, and failure modes.
```

The `name` must match the directory name. The `description` is the single most important field — runtimes show it to the model as the trigger hint, so make it specific.

### Authoring rules

- **Keep skills focused.** One concern per skill.
- **Encode non-obvious invariants.** Skills earn their slot when they capture "you must do X or Y breaks silently". Rewrapping a single command isn't a skill — it's a script.
- **Prefer project scripts over raw commands.** If the workflow is `bun run <x>`, reference the script rather than the raw invocation so the skill survives script changes.
- **Include failure modes.** List the ways the workflow silently breaks; agents use these as a checklist.
- **Update docs, not the skill, for product knowledge.** Skills describe _how to work_ with the template; Fumadocs describes _what the template does_.

## Integration with AI tools

Skills are discovered via the `.agents/skills/` / `.claude/skills` conventions each runtime supports. Reference the directory and the shipped skills from the project's root `AGENTS.md` so agents pick them up on first read:

```markdown
## Skills

Custom skills live in `.agents/skills/`. Shipped:

- `docs` — how to read and keep the Fumadocs site in sync when pages or features change.
```

### Cursor

Skills in `.agents/skills/` are available to Cursor when referenced from `AGENTS.md`.

### GitHub Copilot

Copilot can reference skills when you mention them in comments or prompts.

### Custom AI assistants

The structured format makes skills easy to parse programmatically.
