A skill is a `SKILL.md` under `.agents/skills/<name>/`: a trigger plus a literal procedure for one real task in this repo, its conventions and traps included. `.claude/skills` and `.github/skills` are symlinks to that directory, so Claude Code, Cursor, Codex, and Copilot read the same files.

Only the description is scanned. An agent matches its task against each skill's `Use when ...` and loads one body on a match, so the description is the trigger: a skill whose description names the wrong moment never loads, however good its procedure.

## When you need this

Reach for this page to find the skill for a task, or to add one. For what a fork's `sync` does with the skills it inherits, see [Skills you have customized](/docs/getting-started/cli#skills-you-have-customized).

## The catalog

Each entry is the skill's own summary, the sentence before `Use` in its description, so you see what the agent sees. Entries group by the stage where in the loop a skill fires, in that order: navigate before a task, build while making the change, operate to prove it in the running app, maintain the tooling around the repo, ship the result. Read `codebase-map` before you have a task.

### Navigate

- `codebase-map`: Orient in this repo: which file to edit for a change, how a change ripples across the stack, and how to search the code.

### Build

- `add-package`: Add a new shared workspace package under packages/\*.
- `api-endpoint`: Add a typed Hono API endpoint or WebSocket route: router, OpenAPI docs, validation envelope, and RPC client wiring.
- `db-migration`: Create and apply a Drizzle schema change.
- `design`: Follow and maintain the app's UI conventions.
- `dev`: Start, restart, and verify the dev stack, and sign in as the agent.
- `portless`: Set up and use portless for named local dev server URLs (e.g. https://myapp.localhost instead of http://localhost:3000).
- `runtime-apis`: Prefer Bun-native APIs, else Node built-ins with the node: prefix.

### Operate

- `agent-browser`: Browser automation CLI for AI agents.
- `docker-test`: Build and smoke-test the Docker images with docker compose, and run the golden end-to-end suite against them.
- `ui-verify`: Verify a frontend or UI change in a real browser.

### Maintain

- `audit`: Refresh every dependency and version pin to its latest release, run the dependency security audit, and maintain .github/notes/dependencies.md.
- `fonts`: Add, swap, or remove a self-hosted web font.
- `ignore-sync`: Mirror .gitignore to .dockerignore.
- `shadcn-sync`: Run and reconcile the shadcn component sync (`bun run shadcn:update`).
- `skills-manager`: Keep the AGENTS.md skills tables generated from skill descriptions.
- `writing-for-agents`: Writing documents for agents.

### Ship

- `doc-sync`: Sync docs and skills so they never drift from the code.
- `gh-commit`: Create atomic commits in the conventional format.
- `icebox`: Icebox a raised-but-undecided concern instead of forcing a plan-or-dismiss call: record it with no verdict so the context survives.
- `release`: Cut a production release by promoting canary to main.
- `writing-docs`: Write or rewrite a docs page under web/next/content/docs so it orients the reader, explains the why, and points at the code and skills instead of restating them.

## Vendored skills

`agent-browser`, `portless` and `writing-for-agents` are copied from upstream, and a bare tool name on the `source:` line (`agent-browser`, `portless`, `skills`) is what marks a skill vendored; every other skill in the canonical starter is `source: local`, and a fork's synced skills carry the upstream URL instead. [`vercel-labs/agent-browser`](https://github.com/vercel-labs/agent-browser) ships a discovery stub pointing at the live workflow (`agent-browser skills get core`), so install the CLI first: `npm i -g agent-browser@0.39.0 && agent-browser install`. `portless` is the whole skill from [`vercel-labs/portless`](https://github.com/vercel-labs/portless), as is `writing-for-agents` from [`mattpocock/skills`](https://github.com/mattpocock/skills).

A re-vendor rewrites the folder, and this repo adds to each copy afterwards; the `skills-manager` skill's Re-vendor section holds how each one is re-vendored and what goes back in.

## Writing your own

Make `.agents/skills/<name>/SKILL.md` with `source: local`; the symlinks carry it to every tool. Three rules are the tooling's:

- Keep the `<summary>. Use when <triggers>` shape: the manager cuts the `AGENTS.md` cell at `Use`.
- Quote a description holding `: `, or the manager throws, since strict YAML like GitHub's rejects the bare colon.
- Keep it one file: the CLI syncs only `SKILL.md`, so a sibling file reaches a fork unrebranded and unnamed.

Write the body with `writing-for-agents` loaded; when a convention changes, change its skill in the same commit, and the pre-commit hook regenerates the tables (the `skills-manager` skill).

## It's working if

- `bun .github/scripts/skills-manager.ts --check` prints `AGENTS.md skills tables are up to date.`
- Your skill is in the **Custom** table of `AGENTS.md`, its cell ending where `Use` begins.
